# Заказы Bar Manager — обновление существующего проекта

## Установка

1. Поместите папку `orders-update` из архива внутрь вашей текущей папки BarManager, рядом с package.json. Новый проект не нужен.
2. В Supabase SQL Editor последовательно выполните файлы из orders-update/sql: 01_orders_functions.sql, 02_suppliers.sql, 03_products.sql, 04_products.sql, 05_products.sql, 06_check.sql. Каждый отдельно. Старые шаги создания таблиц 1 и 2 повторять не нужно.
3. При ошибке SQL остановитесь и пришлите полный текст ошибки. Файл 01 применяется транзакцией; существующие заказы не удаляет. Повторный запуск импорта не дублирует записи и не перезаписывает вручную исправленные цены.
4. В терминале VS Code из корня текущего BarManager выполните:

```sh
node orders-update/install.cjs
npx expo start -c
```

Установщик добавит раздел и встроит переход в существующую главную. Перед изменениями сохранит резервные копии в orders-update-backups. ТТК, нормы хранения, инвентаризация и настройки APK не заменяются целиком. Две ошибки присланного проекта исправляются точечно: отсутствующие поля типов Recipe и путь импорта в tests/sections.test.mjs. Если новые файлы заказов уже существуют и отличаются, установщик остановится до любых изменений.

В первом результате 06_check.sql после нового импорта ожидается 231 товар. До ручных исправлений — 8 без цены, 1 без поставщика. Если каталог был заполнен ранее, сохраняются его значения, поэтому число незаполненных полей может отличаться.

## Что работает

- У каждого привязанного бармена собственный заказ ресторана на неделю, начиная с понедельника.
- Ввод количества, сумма строки, общий итог. Черновик сохраняется на сервер кнопкой; несохранённые изменения дополнительно сохраняются на устройстве для этого аккаунта и недели.
- Фильтры по поставщику, разделу, недобору, диапазону цены, сортировка цены, поиск товара.
- Недобор считается по всему заказу независимо от фильтров. Нижняя панель показывает поставщиков, текущую сумму, минимум и недостающую сумму.
- Поставщики, у которых не выбраны товары, не блокируют отправку. Ровно минимальная сумма допускается. Разные поставщики и рестораны не компенсируют недобор друг друга.
- Отправка проверяется на сервере. Пустой заказ, отсутствующая цена, поставщик или минимум и недоступные товары блокируются. Неизвестные значения не считаются нулевыми.
- При изменении цен или минимумов во время работы сохранится черновик, но перед отправкой потребуется проверить новые суммы и повторить отправку.
- Защита от перезаписи заказа второй сессией через номер версии. При конфликте можно явно загрузить серверную версию; эта кнопка заменит текущие несохранённые изменения.
- Отправленные заказы сохраняют снимки цен, наименований, единиц, поставщиков и минимумов. Поздние изменения каталога не изменяют эти заказы.
- Администратор видит рестораны и их статусы, состав каждого заказа, подтверждает отправленный заказ или возвращает его с обязательным комментарием.
- Общая таблица: товары строками, рестораны колонками, количество и сумма. В закупочную сводку входят только отправленные и подтверждённые заказы; черновики доступны отдельно.
- Разные зафиксированные цены одного товара остаются отдельными строками в сводке.
- Вкладка администратора «Цены и минимумы»: редактирование цен, минимума и назначения поставщика товару.

Роли заказов используют существующие order_admin_users и order_user_access. Для доступа к сводке администратор должен быть зарегистрирован в order_admin_users; роль ADMIN в профиле сама по себе не заменяет эту ранее выбранную схему. У бармена должна быть привязка к активному ресторану. Обновление не назначает новые права пользователям.

## Что заполнить в каталоге

Файл needs-review.csv содержит найденные пробелы. У восьми товаров нет цены; у «Сироп малина 1,0» (строка 211) нет поставщика.

Минимумы не заданы у Комплекс бар, озон, БирРитейл, метро, РестИнтернешнл, Гербариста и Кондитерская. Если минимум отсутствует по условиям поставщика, администратор должен явно поставить 0. Пустое поле означает «неизвестно».

Не объединены автоматически два варианта названий: «Кока Кола» / «Кола» (в таблице минимумов 4000 ₽) и «ИП Кошелева» / «Кошелева» (2800 ₽). Если это одни и те же поставщики, задайте соответствующий минимум именно тому названию, которое назначено товарам. Неиспользуемые строки поставщиков не мешают отправке.

Каталог импортирован из двух ваших Excel. Исторические количества из этих файлов не создают новые заказы. Единица заказа в Excel отдельно не указана; объёмы и упаковки сохранены в названиях. Цена применяется к той единице количества, что использовалась в исходной таблице.

## Проверка на телефоне

1. Под барменом откройте Заказы → Заказ, добавьте товары одного поставщика ниже минимума. Убедитесь, что видна недостающая сумма, а отправка недоступна.
2. Сохраните черновик, выйдите и откройте его снова. Количества должны сохраниться.
3. Доберите до минимума, отправьте. Редактирование должно закрыться.
4. Под администратором откройте тот же период: заказ появится в ресторане и сводке.
5. Верните с комментарием, проверьте редактирование барменом и повторную отправку.

## Обновление установленного APK

Изменения файлов на компьютере не обновляют уже установленный APK автоматически. После проверки в Expo Go соберите новую preview-сборку из текущего проекта:

```sh
npx eas-cli@latest build --platform android --profile preview
```

Установите полученный APK как обновление, используя тот же проект, идентификатор приложения и ключ подписи. Установщик не меняет eas.json, app.json, package.json или переменные окружения. Запуск EAS выполняется с вашей учётной записью; новый APK в этом архиве отсутствует.
