# Нормы хранения из Supabase

Эта версия заменяет локальный справочник из предыдущего обновления. Единственный источник строк — существующая таблица public.storage_norms. В базу ничего не добавляется и не изменяется.

## Установка в текущую папку BarManager

1. Остановите Expo: Control+C.
2. Распакуйте ZIP и перенесите папку storage-supabase-update целиком в текущий проект рядом с package.json.
3. Из терминала текущего проекта выполните:

```bash
node storage-supabase-update/install.cjs
npx expo start -c
```

Новые зависимости и SQL-запросы не нужны. Если установщик сообщает о несовпадении структуры, пришлите сообщение и текущие src/app/home.tsx, src/app/_layout.tsx. Не заменяйте их целиком старой версией.

Установщик добавляет/обновляет src/app/storage.tsx, src/lib/storage-rules.ts, src/lib/storage-api.ts. В home.tsx добавляет переход кнопки и восстанавливает её в известной структуре меню/справочника. Экран регистрируется рядом с home в _layout.tsx. Прежние версии изменённых файлов сохраняются в storage-update-backups с расширением .bak. .env, .git, package.json, app.json и eas.json не меняются.

Если вы уже установили предыдущий локальный справочник, его экран заменится. Старый src/data/storage-rules.json больше не используется этим экраном; установщик его не удаляет. После проверки папки установщиков можно убрать из проекта.

## Поля базы

- product_name — название;
- category — группа;
- temperature — температура;
- shelf_life — срок;
- storage_conditions — условия;
- notes — примечания;
- id — ключ строки.

Строки читаются с пользовательской сессией через текущий клиент Supabase и его RLS. Загружаются страницы по 100 строк, чтобы не потерять записи из-за лимита первой страницы. При повторном открытии, нажатии «Обновить» и жесте вниз данные перечитываются. Постоянного локального кэша или подстановки Excel при ошибке нет.

Сроки и температуры отображаются как в базе. Голое значение «72» не превращается автоматически в часы. Поля без значения показываются как «Не указано», подчёркивания срока — «Срок не указан». Звёздочки и индивидуальные примечания сохраняются. Общие пояснения из Excel не добавляются автоматически: схема не содержит отдельного поля для общих правил; выводятся именно notes записей базы.

## Проверка

Войдите в приложение → Нормы хранения. Должны появиться доступные вашему пользователю строки storage_norms. Количество определяется базой; наличие 36 строк в Excel не доказывает, что столько же записей уже в Supabase.

Проверьте поиск по названию, условиям и примечаниям, фильтр группы, возврат назад. Изменение записи в Supabase появится после обновления экрана.

Если список пуст, это может означать отсутствие строк или запрет их чтения через RLS. Если появилась ошибка доступа, пришлите текст сообщения. Не отключайте RLS и не добавляйте service_role в приложение. Существующие политики в этом обновлении не менялись.

## Выполнено локально

Проверка типов, линтер и 11 тестов прошли: поиск, неизменность сроков, загрузка нескольких страниц, ошибки и отмена, пустой результат без подстановки, сохранение конфигурации установщиком и его повторный запуск.

Тесты запросов использовали имитацию ответов Supabase. Подключение к вашей реальной базе и запуск на телефоне ещё требуют проверки: .env не передавался. Установщик подготовлен для известной структуры проекта и проверяет её перед изменениями.
